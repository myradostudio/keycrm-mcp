# keycrm-mcp

[MCP](https://modelcontextprotocol.io)-сервер для API [KeyCRM](https://keycrm.app) — української CRM для торгівлі та сфери послуг. Із ним ШІ-асистент, наприклад Claude, відповідає на запитання про ваші замовлення, покупців і воронки. А якщо ви прямо це дозволите — реєструє новий лід карткою у воронці.

English: [README.md](README.md)

> **Неофіційний проєкт.** Він не пов’язаний із KeyCRM і не схвалений цією компанією. «KeyCRM» — торговельна марка її власника. Ви користуєтеся сервером на власний ризик.

> **Стан: версія 0.1.0, на живому акаунті KeyCRM ще не перевірено.** Сервер написано за офіційним [описом OpenAPI](https://docs.keycrm.app/api.yaml) (версія 1.2.0). Усі тести працюють з імітацією HTTP і звіряють кожен запит зі знімком цього опису. Зі справжнім API-ключем сервер ще ніхто не запускав. Докладніше — у розділі [Обмеження](#обмеження).

## Для чого він

- **Читання.** «Що надійшло сьогодні й що ще не оплачено?», «Знайди замовлення за номером +380501234567», «Які ліди досі на першому етапі?» Асистент читає замовлення, покупців і картки воронок та відповідає простими словами.
- **Реєстрація ліда.** Чат-бот або голосовий агент, що поспілкувався з потенційним клієнтом, може покласти контакт і стислий зміст розмови у воронку, де його підхоплять менеджери. Це єдине, що сервер уміє записувати, і лише після того, як ви це ввімкнете.

Того, що вже є в CRM, сервер не змінює і не видаляє: такого інструмента в ньому немає.

## Швидкий старт

Потрібні Node.js 20 або новіший та **API-ключ** вашого акаунта KeyCRM. Де його взяти, KeyCRM пояснює у своєму [довідковому центрі](https://help.keycrm.app/uk/process-automation-api-and-more/where-to-get-an-api-key).

> **В npm пакета ще немає.** Доки перший реліз не опубліковано, команди `npx -y @myradostudio/keycrm-mcp` нижче не працюватимуть. Запускайте сервер із вихідного коду: `git clone https://github.com/myradostudio/keycrm-mcp`, далі `npm install` і `npm run build` у цій теці, а в налаштуваннях нижче вкажіть `"command": "node"` і `"args": ["/абсолютний/шлях/до/keycrm-mcp/dist/index.js"]`.

### Claude Desktop

Додайте сервер до `claude_desktop_config.json` (Settings → Developer → Edit Config):

```json
{
  "mcpServers": {
    "keycrm": {
      "command": "npx",
      "args": ["-y", "@myradostudio/keycrm-mcp"],
      "env": {
        "KEYCRM_API_KEY": "ваш API-ключ"
      }
    }
  }
}
```

Якщо у Windows сервер не запускається, вкажіть `"command": "cmd"` і `"args": ["/c", "npx", "-y", "@myradostudio/keycrm-mcp"]`.

### Claude Code

```bash
claude mcp add --transport stdio \
  --env KEYCRM_API_KEY=ваш-api-ключ \
  keycrm -- npx -y @myradostudio/keycrm-mcp
```

### Cursor

Додайте такий самий блок до `~/.cursor/mcp.json` (для всіх проєктів) або `.cursor/mcp.json` (для одного проєкту):

```json
{
  "mcpServers": {
    "keycrm": {
      "command": "npx",
      "args": ["-y", "@myradostudio/keycrm-mcp"],
      "env": {
        "KEYCRM_API_KEY": "ваш API-ключ"
      }
    }
  }
}
```

Будь-який інший MCP-клієнт, що вміє запускати локальний stdio-сервер, налаштовується так само: запустіть `npx -y @myradostudio/keycrm-mcp` зі змінними середовища з таблиці нижче.

Після цього можна запитати, наприклад:

- «Покажи вчорашні замовлення з покупцями й сумами. Які з них не оплачено?»
- «Чи є покупець із телефоном +380501234567? Що він замовляв?»
- «Які в нас воронки й скільки лідів на кожному етапі першої?»
- З увімкненим інструментом запису: «Зареєструй лід: Ірина, +380501234567, питала про оптові ціни, передзвонити завтра о 10».

## Налаштування

Сервер налаштовується лише змінними середовища. Під час запуску він їх перевіряє і, якщо щось не так, завершує роботу з поясненням у stderr.

| Змінна | Обов’язкова | Типове значення | Призначення |
| --- | --- | --- | --- |
| `KEYCRM_API_KEY` | так | | API-ключ вашого акаунта KeyCRM. Лише сам ключ, без `Bearer`. |
| `KEYCRM_API_URL` | ні | `https://openapi.keycrm.app` | Адреса API. Лише `https://` (звичайний `http://` дозволено тільки для localhost). |
| `KEYCRM_ALLOW_WRITE` | ні | вимкнено | Значення `1` вмикає інструмент запису. Якщо значення не належить до `1`/`true`/`yes`/`on` чи `0`/`false`/`no`/`off`, сервер не запуститься. |

## Інструменти

Усі дати й час у KeyCRM — в **UTC**. Аргументи з датою приймають ISO 8601 зі зміщенням від UTC (наприклад, `2026-10-01T00:00:00+03:00`), і сервер переводить їх в UTC; результати повертаються в UTC, як їх надсилає KeyCRM. Суми — звичайні числа у валюті джерела замовлення, не в копійках. Сервер повідомляє про це моделі.

### Інструменти читання (доступні завжди)

| Інструмент | Що повертає | Запит до API |
| --- | --- | --- |
| `list_orders` | Замовлення із сумами, статусом оплати й датами; фільтри за статусом, джерелом, телефоном чи e-mail покупця, статусом оплати, трекінг-кодом і періодами | `GET /order` |
| `get_order` | Одне замовлення повністю | `GET /order/{orderId}` |
| `list_order_statuses` | Активні статуси замовлень | `GET /order/status` |
| `list_order_sources` | Джерела замовлень і лідів з їхньою валютою | `GET /order/source` |
| `list_buyers` | Покупців; фільтри за ідентифікатором, телефоном, e-mail і періодами | `GET /buyer` |
| `get_buyer` | Одного покупця повністю | `GET /buyer/{buyerId}` |
| `list_pipelines` | Воронки акаунта | `GET /pipelines` |
| `list_pipeline_statuses` | Етапи однієї воронки з кількістю лідів на кожному | `GET /pipelines/{pipelineId}/statuses` |
| `list_pipeline_cards` | Картки воронок (ліди); фільтри за воронкою, етапом, джерелом і періодами | `GET /pipelines/cards` |
| `get_pipeline_card` | Одну картку воронки повністю | `GET /pipelines/cards/{cardId}` |
| `list_users` | Користувачів акаунта, тобто менеджерів | `GET /users` |

Усі шляхи — відносно `https://openapi.keycrm.app/v1`.

Інструменти-списки повертають стислі зведення та блок `pagination`. Типовий розмір сторінки — 15, як в API, найбільший — 50, це максимум API; поле `next_page` підказує моделі, як отримати продовження.

Пов’язані дані повертаються лише на запит через `include` — так само, як в API: наприклад, `["buyer", "status", "products.offer"]` для замовлень або `["contact.client", "status"]` для карток воронок. Інструменти `get_*` пропонують усі значення, які опис називає допустимими, а окремий тест стежить, щоб обидва переліки збігалися. Інструменти-списки пропонують лише ті значення, які видно в їхніх зведеннях, тож запит ніколи не витрачається на дані, які було б відкинуто: адреси доставки повертає `get_buyer`, UTM-мітки й користувацькі поля — `get_order` і `get_pipeline_card`.

### Інструмент запису (лише з `KEYCRM_ALLOW_WRITE=1`)

| Інструмент | Що робить | Запит до API |
| --- | --- | --- |
| `create_pipeline_card` | Створює картку у воронці: лід із контактом, назвою, коментарем для менеджера, джерелом, відповідальним менеджером, часом наступного контакту, UTM-мітками й користувацькими полями | `POST /pipelines/cards` |

Контакт задається або іменем із телефоном чи e-mail, або ідентифікатором наявного покупця. Якщо не вказати воронку, KeyCRM візьме першу зі списку.

## Модель безпеки

У CRM зберігаються персональні дані ваших клієнтів, а менеджери діють за тим, що в ній з’являється, тому сервер навмисно обережний.

- **Без вашого дозволу — тільки читання.** Без `KEYCRM_ALLOW_WRITE=1` інструмент запису взагалі не реєструється: модель його не бачить і викликати не може. Кожен інструмент читання надсилає лише запити `GET`, і це перевіряє окремий тест.
- **Наявне змінити не можна.** Немає інструмента, який оновлює чи видаляє замовлення, покупця або картку.
- **Чесні анотації.** Інструменти читання мають `readOnlyHint: true`. `create_pipeline_card` додає запис і позначений як запис без руйнування даних і не ідемпотентний. Чи показувати підтвердження і як саме, вирішує ваш MCP-клієнт; не вимикайте підтвердження кожного виклику для інструмента запису.
- **Сувора перевірка вхідних даних.** Кожен інструмент відхиляє аргументи, яких не знає, тож фільтр, якого в API немає, не буде мовчки проігноровано. Період потребує обох меж, а дату, якої не існує (31 квітня), сервер відхиляє, а не переносить на наступний місяць. Контакт потребує телефону, e-mail або ідентифікатора покупця; самого лише імені замало.
- **Жодних повторів наосліп.** Сервер сам ніколи не повторює запит. Якщо створення картки завершилося без певної відповіді (сплив час очікування, обірвалося з’єднання, шлюз повернув помилку, прийшла відповідь HTTP 429 або відповідь не вдалося прочитати), інструмент повідомляє, що результат невідомий, і пояснює, як його перевірити. KeyCRM не описує способу зробити цей запит безпечним для повтору, тож повтор наосліп міг би створити той самий лід двічі.
- **У межах задокументованої частоти.** KeyCRM дозволяє 20 запитів за хвилину на один API-ключ. Сервер рахує власні запити: коли ліміт вичерпано, він чекає вільного моменту до п’яти секунд, а далі інструмент не надсилає запит і повідомляє, коли спробувати знову.
- **Ключ зберігається лише у вас.** Сервер читає його зі змінної середовища, використовує лише для запитів до `KEYCRM_API_URL` і ніколи не виводить у stdout чи stderr. Кожну відповідь API сервер очищає від ключа ще до того, як щось із неї будує, тож і в результат інструмента він потрапити не може. За перенаправленнями сервер не переходить, тому ні ключ, ні тіло запиту не потраплять на інший хост.
- **Моделі — менше даних.** Інструменти-списки повертають зведення. Замовлення чи картка показує свого покупця або контактну особу лише тоді, коли модель просить про це через `include`; `list_buyers` — це список клієнтів, тож він за своєю суттю повертає їхні імена, телефони й e-mail. `get_order`, `get_buyer` і `get_pipeline_card` повертають повні записи.
- **Жодної телеметрії; дані бізнесу не потрапляють у журнали.** У stderr потрапляють лише повідомлення під час запуску (помилки налаштувань і рядок із режимом роботи) та тип помилки транспорту. Запити й відповіді ніде не записуються.

Двох речей сервер за вас не зробить. По-перше, усе, що повертає інструмент, потрапляє до ШІ-моделі, якою ви користуєтеся, і до її постачальника; замовлення й покупці — це персональні дані, тож зважте, чи прийнятно й чи законно це для ваших клієнтів. По-друге, коментарі, імена й назви з KeyCRM модель отримує без змін, і в них можуть бути чужі інструкції (prompt injection); коментар покупця пише ваш клієнт. Це ще одна причина підтверджувати кожен виклик запису власноруч.

## Обмеження

- **Сервер не перевірено на живому акаунті.** Запити звірено з описом OpenAPI, а він описує структуру даних, а не поведінку. Обробку відповідей і тексти помилок реалізовано за документацією.
- **Фільтри взято з прикладів опису.** KeyCRM оголошує `filter` довільним об’єктом, а доступні поля показує лише в прикладах. Сервер пропонує саме ці поля. Як кожне з них порівнює значення (точно чи частково, як має бути записано телефон), не задокументовано; це треба перевірити на живому акаунті.
- **Період потребує обох меж.** Фільтри — це діапазони (`created_between`, `updated_between`, `shipping_between`), тому інструмент вимагає і початок, і кінець.
- **Ключ — це весь акаунт.** Опис не згадує жодних обмежень доступу для API-ключа.
- **Чого немає:** створення чи зміни замовлень і покупців, переміщення картки на інший етап, оплат і витрат, товарів, залишків, компаній, тегів, файлів, дзвінків, налаштування користувацьких полів, вебхуків.
- **`create_pipeline_card` не надсилає товари й оплати**, хоча API їх приймає.
- **`get_pipeline_card`.** Опис подає відповідь для однієї картки як посторінковий список. Сервер повертає той запис цього списку, ідентифікатор якого збігається із запитаним, приймає також звичайний об’єкт і радше повідомить про помилку, ніж видасть іншу картку за запитану.
- **Подробиці помилок.** Для помилки опис показує лише `{"message": "…"}`. Якщо KeyCRM надсилає перелік помилок по полях у `errors`, сервер його виводить; ця частина — припущення про незадокументований формат, і вона з’являється лише тоді, коли такі дані є.
- **Частоту запитів сервер рахує лише для себе.** KeyCRM рахує запити за API-ключем. Інші програми з тим самим ключем витрачають той самий ліміт, тож API однаково може відмовити.
- **Один акаунт на один екземпляр сервера.**
- **Час очікування відповіді фіксований** — 30 секунд на запит.

## Розробка

```bash
npm install
npm run lint          # tsc --noEmit для src/ і tests/
npm test              # збирає dist/ і тести, потім запускає їх через node:test
npm run spec:update   # оновлює знімок OpenAPI з docs.keycrm.app
```

- `src/endpoints.ts` — перелік методів API, які викликає сервер. `tests/spec.test.ts` порівнює його з `spec/keycrm-api.snapshot.json` — скороченою копією офіційного опису OpenAPI (лише параметри, схеми запитів, назви фільтрів і допустимі значення `include` для цих методів).
- Кожен тест інструмента викликає його через справжній MCP-клієнт. Коли тест завершується, кожен записаний у ньому запит проходить через `assertMatchesSpec`; ця функція звіряє шлях, параметри, фільтри, заголовки й тіло запиту зі знімком.
- `tests/e2e.test.ts` запускає зібраний сервер окремим процесом через stdio; замість API працює локальна HTTP-заглушка.
- Перевірити сервер уручну: `npx @modelcontextprotocol/inspector node dist/index.js`.

Сервер використовує офіційний TypeScript SDK ([`@modelcontextprotocol/server`](https://www.npmjs.com/package/@modelcontextprotocol/server)) і `zod`; інших залежностей для роботи він не має.

Будемо раді повідомленням про помилки та пул-реквестам. Про вразливості пишіть так, як описано в [SECURITY.md](SECURITY.md).
